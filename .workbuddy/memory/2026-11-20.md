# 2026-11-20 工作日志

## Mermaid 图布局优化（Agent 设计模式全书结构图）

- **问题**：`docs/ai/agent/index.md` 的全书结构图用 `flowchart TD`，但「下篇」节点扇出 7 个带 `<br/>` 长副标题的子节点，导致横向爆宽（实测 viewBox 2777×222，宽高比 12.5:1），完全看不清。
- **优化**：改为两个 `subgraph`（上篇/下篇）+ 组内 `direction TB` + 链式连接 + `UP --> DOWN` 连接容器本身（避免外部边让 direction 失效）。信息零丢失。
- **效果**：viewBox 346×1668，宽高比 0.21:1，宽度降 87.5%；Chrome 截图目视验证清晰无溢出。
- **方法论沉淀**：新建 `mermaid-图最佳实践.md`（诊断口诀 + 5 手法 + 3 坑 + 验证脚本 + 实测对照）。
- **可复用工具**：`/tmp/mermaid_width.py` —— 从 md 提取 mermaid 块，用本机 Chrome + 本地 mermaid bundle 渲染，量 W/H/ratio。以后优化任何图先跑这个脚本拿量化基线。
- **关键技术结论**：
  - TD/LR 只定主轴，不定每层排布；一对多扇出仍会横向并排——控宽先压「同层兄弟节点数 × 单节点宽度」。
  - subgraph 内节点连到外部时，该 subgraph 的 `direction` 被忽略、继承父图方向（官方明确）；连容器本身则保持。
  - 本机 mermaid 渲染验证链路：本地 `node_modules/mermaid/dist/mermaid.min.js` + Chrome headless `--dump-dom` / `--screenshot`，无需联网。
- **验证**：`npm run build` 通过，图源码进入 `dist/static/js/async/*.js`（mermaid 客户端渲染，html 内不含源码；搜中文节点名或 `UP --` 可定位）。
